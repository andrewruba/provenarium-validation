# Provenarium Validation v0.1.3

## Changes

- The IOQ authoring prompt asks for a visible result and a matching record
  identifier, when the app provides one, before checking numeric results.
- The hosted dilution demo accepts large finite inputs and retains
  three-decimal formatting after saving and reloading. It rejects nonfinite
  inputs and unrepresentable results.
- The demo's Calculation reference explains that a displayed or exported
  `0.000 mL` can represent a positive volume below `0.0005 mL`.

## Install and run

Use Node.js 26 and npm on macOS or Linux.

```sh
npm install --global https://github.com/andrewruba/provenarium-validation/releases/download/v0.1.3/provenarium-validation-0.1.3.tgz
provenarium --version
provenarium validate --context ../my-app --url https://app.example.com
```

Start in a new project directory to draft requirements and generate the IOQ.
Review and approve the requirements before the CLI dry-runs the browser tests.
After a passing dry run, the CLI executes the checked tests and prints the
execution report path. Review any failures in the saved dry-run report.

The release workflow verifies the attached npm archive on macOS and Ubuntu.
`release.json` identifies the source commit and archive digest. Use
`SHA256SUMS` to verify the downloaded archive.
